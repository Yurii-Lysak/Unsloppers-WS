- (capability) CAP-1 Access Control, Roles & Employee Profile (Epic 1, incl. Profile Sharing 4.8) — intent: resolve every viewer's access role per subject (Self/Manager/PP/Colleague/HR Admin) from the transitive closure of reports-to and project-assignment relationships, assemble each profile from exactly the S1-S16 sections that role is entitled to, enforce the colleague whitelist and the S7 manager/PM note-visibility exception, let HR Admin define and grant functional roles/permissions as runtime data with no deploy, and let a manager generate a time-limited, revocable, logged, per-section shareable profile link — success: every audience x relationship-path x section combination is covered by a negative test asserting the API/UI/export/search never returns a '-' cell, an unflagged S7 record, or a non-whitelisted colleague field; a new functional role created via UI is assignable and enforced with zero code change; access is re-resolved per request with no session-cached grant surviving a relationship change
- (capability) CAP-2 All Employees Directory & Custom Fields (Epic 3) — intent: one filterable/sortable employee list scoped per viewer's access where any built-in, derived, or custom field is usable as a column/filter/sort key, custom fields are defined at runtime with no schema migration, list cells are inline-editable subject to the access matrix, filter+column configurations save as named shareable views, and the current view exports to .xlsx containing only columns the exporter can see — success: a newly created custom field is immediately usable as filter/column/export with no deploy; a saved view is reusable and shareable; the list responds within 2s at 500+ records under arbitrary filters including permission resolution
- (capability) CAP-3 Self-Service (Epic 2) — intent: let an employee view their own employment summary, edit their own personal/emergency contacts and residential address, upload a photo and certificates, and view their own timeline, leaves, projects, CDS/IDP, mentorship status, shared feedback, flagged management notes, and action items, marking IDP items and action items complete themselves — success: an employee completes every listed self-service action without manager/PP involvement, and never sees their own risk level or an unflagged management note
- (capability) CAP-4 Action Items and Tasks (Epic 4) — intent: one task entity (title, description, assignee, author, due date, optional link, status, completion date, source) creatable manually by a manager/PP/permitted role for anyone in their access scope, creatable automatically by form-campaign activation (one per recipient), completable by the assignee, cancellable by the author with a reason, and rendered overdue everywhere it appears once its due date passes — success: lifecycle open→completed is correct for both manual and campaign-sourced items; overdue derivation is identical everywhere it's displayed; cancellation is scoped by historical authorship not live access
- (capability) CAP-5 Risks and Risk Dashboard (Epic 5) — intent: record a per-employee risk (level low/need attention/medium/high/leaver, description, details, date) with retained history, show a trend arrow vs. the previous record, and provide a Risk Dashboard with severity-sorted counts and a drill-through table filterable by unit/department/project/PP/manager, scoped to the viewer's Manager/PP access — success: current level is always the most recent record; trend arrow appears only on an actual level change; section and dashboard are never visible to the employee themself
- (capability) CAP-6 Resourcing (Epic 6) — intent: let a DM/PM/permitted role create a resourcing request (vacancy details, comp level, duration, workload, optional project link), let a UM fulfil it by proposing internal employees or external PeopleForce candidates, let the DM approve/reject each proposal with a written reason (using profile-sharing for internal candidates the DM lacks access to), and retain full request history on both the request and the employee's profile (S15) — success: an unattached request with no project is a valid normal state; every proposal records proposed→approved/rejected with feedback; external-candidate review works via live PeopleForce integration or, as an explicit sanctioned fallback, a link out to PeopleForce
- (capability) CAP-7 Career Timeline (Epic 7) — intent: auto-generate a timeline event via one system-wide event-writer whenever a tracked change occurs (joining, grade/position/department change, FTE↔subcontractor transition, extended leave, mentorship pair start/end), and let PP/UM manually add/edit/delete events for historical backfill or correction, presented as a readable chronological timeline on the profile — success: every tracked change type produces exactly one system-generated event with no separately maintained record; a manual correction is never silently overwritten by a later system-generated event covering the same window (conflict is skipped and logged)
- (capability) CAP-8 CDS: Career Development System (Epic 8) — intent: show each profile a resolved link to the current skills-matrix file for that person's department+position via a maintained dictionary (not encoded structure), an assessment log (date, assessor, result-file link, text conclusion) editable by manager/PP, and an IDP (description, deadline, external file link, complete checkbox) the employee can self-complete, plus All-Employees filters for last-assessment date (with 'never assessed' as a distinct selectable option) and has-open-IDP — success: updating the centrally maintained matrix file changes what every affected profile's link resolves to with no per-profile update; 'never assessed' is selectable and distinct from any date-range result
- (capability) CAP-9 Mentorship Hub (Epic 9) — intent: let an employee self-flag open-to-mentoring and see their own mentor/mentees; let a manager/PP browse everyone flagged open-to-mentor, assign a mentor-mentee pair (flips mentor status to 'mentor' on first pair), end a pair only with required closing feedback recorded (reverting status to 'open to mentoring' only if the self-flag is still on, else to no status, per D4), and view all pairs with dates; show the mentor in every profile header alongside manager and PP — success: a pair cannot be ended without closing feedback; mentor status transitions follow the self-flag rule exactly even when the flag was turned off mid-pair; every pair end writes a CAP-7 timeline event
- (capability) CAP-10 Forms & Survey Campaigns (Epic 10) — intent: let a PP/manager/permitted role create a draft form campaign (title, description, purpose, external form link, due date), build its audience via the CAP-2 filter engine or a saved view with individual add/remove, activate it to atomically freeze the audience and generate one CAP-4 action item per recipient, and track per-person completion (completed/not completed/overdue) without ever reading or verifying the external form — success: frozen audience never changes post-activation; activation is all-or-nothing with no partial state; a recipient's own action-item completion is the only trusted completion signal
- (capability) CAP-11 Feedback (Epic 11) — intent: let a manager/PP record a feedback record on a profile (subject, author, date, context, body) with a visibility flag defaulting to management-only and flippable to shared-with-employee, view records chronologically with period-over-period comparison, and let a manager/PP request feedback from specific named colleagues via a CAP-10 campaign targeted individually rather than by filter, with the requester manually authoring the resulting Feedback record after reading the external form's actual responses — success: flipping visibility makes a record immediately visible on the employee's own profile with no stale grant; a colleague never gets read access to feedback about someone else; completing a feedback-request campaign never auto-creates a Feedback record
- (capability) CAP-12 Dashboards (Epic 12) — intent: one shared dashboard engine serving four role-scoped views — Unit Manager (by people), Delivery Manager (by project, with an all-projects/single-project selector recalculating every counter), Project Manager (DM view scoped to own projects), People Partner (by department/project, no resourcing block) — each showing summary counters, a people/project table with risk and leave status, and the viewer's own overdue-highlighted action items — success: selecting a DM project filters the whole page and every counter to it, clearing it restores the all-projects aggregate; the PP dashboard never renders a resourcing block
- (capability) CAP-13 External Integrations: Timetracker & PeopleForce (Epic 13) — intent: integrate the timetracker's Leaves API (S10) and Projects & People API (S11, which also feeds the CAP-1 project-assignment access leg) against real endpoints, integrate PeopleForce for external-candidate data (CAP-6) and vacancy source-of-truth, and resolve cross-system identity via an explicit mapping table keyed by (system, external ID) rather than email, with a supersession pointer for re-hires — success: a timetracker sync outage fails safe for access (an unconfirmed project assignment never grants Manager access) and fails soft for display ('temporarily unavailable' instead of blocking the profile); where PeopleForce integration isn't completed in time, a link out to PeopleForce is an accepted sanctioned fallback, never a silent gap
